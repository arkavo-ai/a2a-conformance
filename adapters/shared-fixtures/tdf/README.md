# Shared TDF test fixtures

**TEST KEYS ONLY — deliberately committed.** KAS protocol/rewrap is out of
scope (spec §6); these stand in for the unwrapped Data Encryption Key (DEK) a
real KAS would provide, so both implementations encrypt/decrypt against
identical key material.

- `test-dek.bin` — the 32-byte AES-256 DEK (bytes 0x00..0x1f). The "correct"
  key both peers hold.
- `wrong-dek.bin` — the DEK with every byte flipped; used by
  `tdf-part-wrong-key-fails-closed` to prove GCM auth failure surfaces a
  part-level `#error`, never silent plaintext.
- `manifest.json` (generated by the Rust impl, cross-verified by Swift):
  NanoTDF-shaped inline parts and a b3 URL record for known plaintexts, plus
  BLAKE3 digests — the cross-language byte-level contract, as identity's works.

Cipher AES-256-GCM (swift-crypto `AES.GCM` / Rust `aes-gcm`); integrity BLAKE3
(`b3/<hex>`). Profile pinned in `adapters/TDF-HARNESS.md`.
