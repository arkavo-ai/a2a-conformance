# Shared identity test fixtures

**TEST KEYS ONLY — deliberately committed.** These P-256 keypairs exist so the
Rust and Swift identity implementations (and the conformance harnesses) verify
against the same cryptographic ground truth. They carry no real trust:

- `test-issuer.*` — stands in for the identity.arkavo.net AIA when harnesses
  mint CWTs (`iss` is still the spec-pinned issuer string; the *trust root* is
  injected verifier config, which is how the real verifier works too).
- `test-client-agent.*` — the presenting agent's keypair (`sub` DID, `cnf` key).
- `test-server-agent.*` — the target agent's keypair (card signing, `aud` DID).

`manifest.json` (generated by the Rust implementation, verified byte-for-byte
by Swift) records the derived `did:key` identifiers and cross-language vectors:
a valid CWT, an expired CWT, a wrong-audience CWT, a signed agent card, and a
tampered variant. Both implementations must agree on every artifact.
